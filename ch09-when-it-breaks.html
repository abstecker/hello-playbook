When it breaks

The greeter in the last chapter answers every line it is given. This one learns to refuse one, first badly and then well, and you can try both versions on this page.

A refusal that panics

Nobody's name is a paragraph. Say the greeter takes forty characters at most, and say so the quickest way Rust allows: an assert!.

💾 src/session.rs · L1–L59 · step 029 of hello-playbook · diff · browse

//! One line in, one reply out: the seam every shell drives.

use crate::greet;

/// The longest name the greeter takes, in characters.
const LONGEST: usize = 40;

/// A conversation with the greeter.
#[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen)]
#[derive(Debug, Default)]
pub struct Session;

#[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen)]
impl Session {
    /// A new conversation.
    #[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen(constructor))]
    #[must_use]
    pub fn new() -> Self {
        #[cfg(feature = "wasm")]
        console_error_panic_hook::set_once();
        Self
    }

    /// Answer one line: greet the name on it, or the world if it is blank.
    ///
    /// # Panics
    ///
    /// If the name is longer than [`LONGEST`] characters.
    pub fn eval(&mut self, line: &str) -> String {
        let name = line.trim();
        let length = name.chars().count();
        assert!(
            length <= LONGEST,
            "a name of {length} characters is longer than the {LONGEST} this greeter takes"
        );
        greet(if name.is_empty() { "world" } else { name })
    }
}

#[cfg(test)]
mod tests {
    use super::Session;

    #[test]
    fn a_name_is_greeted() {
        assert_eq!(Session::new().eval("Ada"), "Hello, Ada!");
    }

    #[test]
    fn a_blank_line_greets_the_world() {
        assert_eq!(Session::new().eval("  "), "Hello, world!");
    }

    #[test]
    #[should_panic(expected = "longer than the 40")]
    fn a_long_name_panics() {
        Session::new().eval(&"a".repeat(41));
    }
}

$> git checkout step-029-long-names

The test says what the assertion does, and the gate holds it to that: a long name panics, with those words. It passes. Whether a panic is the right thing to do is a question no test here asks.

Try it. Ada is still greeted. Then give it a long name — Hubert Blaine Wolfeschlegelsteinhausenbergerdorff is forty-nine characters.

$ cargo run -q --example repl · step 029 of hello-playbook

> Ada
Hello, Ada!

In a terminal the panic ends the program: the message, where it happened, and the shell is gone. In this page the same thing happens to the module. The panic is printed where a reply would be, because chapter 8 kept its message, and the prompt closes, because a WebAssembly module that has panicked is in no state to take another line. Reloading the page is the only way back.

That is what a panic is for: a state the program cannot go on from. A long name is not one. It is a line the greeter does not like, and the person who typed it is still there.

A refusal that answers

//! One line in, one reply out: the seam every shell drives.

use crate::greet;

/// The longest name the greeter takes, in characters.
const LONGEST: usize = 40;

/// A conversation with the greeter.
#[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen)]
#[derive(Debug, Default)]
pub struct Session;

#[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen)]
impl Session {
    /// A new conversation.
    #[cfg_attr(feature = "wasm", wasm_bindgen::prelude::wasm_bindgen(constructor))]
    #[must_use]
    pub fn new() -> Self {
        #[cfg(feature = "wasm")]
        console_error_panic_hook::set_once();
        Self
    }

    /// Answer one line: greet the name on it, or the world if it is blank,
    /// or say why a name is too long.
    pub fn eval(&mut self, line: &str) -> String {
        let name = line.trim();
        let length = name.chars().count();
        if length > LONGEST {
            return format!(
                "That name is {length} characters; the most this greeter takes is {LONGEST}."
            );
        }
        greet(if name.is_empty() { "world" } else { name })
    }
}

#[cfg(test)]
mod tests {
    use super::Session;

    #[test]
    fn a_name_is_greeted() {
        assert_eq!(Session::new().eval("Ada"), "Hello, Ada!");
    }

    #[test]
    fn a_blank_line_greets_the_world() {
        assert_eq!(Session::new().eval("  "), "Hello, world!");
    }

    #[test]
    fn a_long_name_is_answered() {
        assert_eq!(
            Session::new().eval(&"a".repeat(41)),
            "That name is 41 characters; the most this greeter takes is 40."
        );
    }
}

$> git checkout step-030-long-names-reply

The refusal is a reply now, like any other. eval still takes a line and returns a line, so neither shell changes, and the test that pinned the panic is replaced by one that pins the answer.

This time the transcript can hold the long name, because the session outlives it. bower verify types all three lines into the terminal shell and fails the book if any reply differs. The prompt under it is this step's module, not the one above: each control runs the code as it stood at its own step.
